## Перед запуском для студентов

1. Railway: подключён Volume с путём `/data` и задан `DB_PATH=/data/almau.db`, иначе база стирается при каждом деплое.
2. Railway Variables: `CORS_ORIGIN=https://almau-messenger.vercel.app`, свой длинный `ADMIN_TOKEN`, ключи Brevo
   (`BREVO_API_KEY`, `BREVO_SENDER_EMAIL` — без них письма клубов и напоминания не уходят), `SITE_URL` — адрес сайта для ссылок в письмах.
   Резервная копия базы: «Админка → Демо-данные → Скачать резервную копию».
3. Назначить первого администратора (README → «Первый администратор»).
4. Удалить демо-аккаунты: «Админка → Демо-данные → Удалить всех демо» и поставить `SEED_DEMO_PEOPLE=0`, иначе они создадутся снова при перезапуске. Преподаватели из расписания AlmaU при этом остаются (они нужны дисциплинам каталога). Для своего аккаунта с оценками-примером: `SHOWCASE_GRADES_FOR` (по умолчанию «Хасанов Хамид»; пусто — ни у кого).
5. Railway: тариф Hobby ($5), лимит расходов в Settings → Usage.

## Решения команды на будущее

- Учебный план AlmaU (22.11.2026): 25 специальностей, 229 дисциплин, 188 преподавателей из файлов расписания (`site/data/curriculum.json`, как собрать — `tools/curriculum/`). Дни, время и какой преподаватель ведёт вариант — случайно. Студент при регистрации выбирает курс 1–4 и специальность и сразу получает расписание. 4 курс в файлах есть только у МВД. 350 демо-студентов с оценками ТК1, РК1, ТК2; РК2 и сессии ещё нет. Итог = (РК1 + РК2) / 2 × 60% + Сессия × 40%.

- Telegram-бот удалён из кода 20.11.2026 (остался в истории git). Подбор собеседника по интересам и напоминания о походах нужно перенести на сайт.
- Блок 3 описывает историю проекта, поэтому бот там остаётся как пакет WBS. Источники KPI `/stats` и `/club` были в боте; теперь цифры берутся из «Админки» на сайте.
- Вуз определяется по корпоративной почте студента. Запускаемся с AlmaU, другие вузы подключаем позже, у каждого вуза будет свой администратор.
- Свой домен (например, pople.kz) ещё не куплен.

## Отложенные доработки

По приоритету, подробно — в истории обсуждения с ИИ-ассистентом.

- **P0:** CI с автотестами в GitHub Actions; резервные копии базы; регистрация только с почтой вуза; окно времени и перемешивание вопросов в экзаменах; мониторинг `/health`.
- **P1:** уведомления (push и почта), напоминания о походах на сайте, замена опроса сервера на SSE, посещаемость списком, экспорт ведомости в CSV и расписания в календарь, страницы партнёров из данных, роль организатора клуба.
- **Позже:** переход с SQLite на PostgreSQL, мультивузовость, свой домен, казахский язык, учебные группы, обмен материалами.
- **Отдел расписания:** может создавать дисциплины, проверка накладок по времени и аудиториям.
