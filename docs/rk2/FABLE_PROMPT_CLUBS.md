# Промпт для Fable: клубная система Pople

Ты работаешь в репозитории `taekeanoshi/Almau_messanger` над платформой **Pople** (сайт
https://almau-messenger.vercel.app, API на Railway). Сначала прочитай `CLAUDE.md`,
`README.md`, `docs/README.md` и **`docs/rk2/CLUB_SYSTEM.md` — это техзадание**.
Фокус команды сейчас — клубы: им нужен максимальный комфорт. Через неделю рубежный
контроль, поэтому делаем MVP, но законченный: работает на сайте, проверен в браузере,
покрыт тестами.

## Важное о коде
- Сервер: Python 3.13, aiohttp, SQLite (`bot/`). Схему меняй только через
  `Database._migrate()`, без потери данных. Новые эндпоинты проверяют роль.
- Сайт: `site/` без фреймворков, inline-скрипты запрещены CSP (`site/vercel.json`).
- Походы уже есть в `bot/hikes.py`: таблица `hikes` с `club_id`, лимитом мест, листом
  ожидания, отметкой «Я спустился», записи в `hike_signups`. **Обобщи их в события клуба**
  (поле типа события), а не создавай параллельную систему. Существующая страница Summit
  Seekers и её записи должны продолжить работать.
- Ивенты в `site/data/events.json` — статичная афиша; события клубов из базы должны
  появляться в афише рядом с ними.
- Роли сейчас: student, teacher, registrar, admin (`bot/admin.py`, `bot/academics.py`).
- В репозиторий пишет ещё напарник со своим ИИ: перед работой `git pull`, маленькие коммиты,
  `pytest -q` зелёный перед каждым пушем, чужое не удаляй без согласия.

## Задачи (по порядку, после каждой — коммит и пуш)
1. **Роль `organizer`** с привязкой к клубу (организатор видит и меняет только свой клуб;
   админ назначает организатора в «Админке»).
2. **Демо-аккаунты**: студент и организатор Summit Seekers, как в `CLUB_SYSTEM.md`. Создаются
   при старте сервера, только если задана переменная `DEMO_LOGIN_PASSWORD`; пароль нигде в
   коде и документах не пиши. Оба `is_demo=1`. Студенту — подписки, запись на поход и место
   в листе ожидания, чтобы на показе всё было видно сразу.
3. **Кабинет организатора**: дашборд; создать / изменить / отменить / дублировать событие
   (шаблоны: поход, вечеринка, игра, лекция, билеты); список записавшихся; лист ожидания;
   выгрузка CSV; чек-ин по списку с подсчётом явки.
4. **Студенту**: подписка на клуб, блок «Мои клубы» на главной, «Мои записи» (с позицией в
   листе ожидания и отменой), уведомления на сайте (колокольчик): запись подтверждена,
   освободилось место, событие изменено или отменено, напоминание за 24 часа.
5. **Метки тарифа**: в кабинете у функций тарифа «Клуб» маленькая метка «в тарифе Клуб».
   Во время пилота всё открыто.
6. Если останется время: QR-билет студента и сканер чек-ина в кабинете; письма-напоминания
   через Brevo (уже подключён для кодов); отзыв после события.

## Правила
- Не придумывай клубы, события, людей и цифры как настоящие. Демо-данные помечены.
- Интерфейс и тексты — на русском, коротко и по-человечески.
- Проверяй каждую задачу в настоящем браузере (Playwright, компьютер и телефон 390px):
  войди под демо-студентом и демо-организатором и пройди их путь из `CLUB_SYSTEM.md`.
- **После каждой задачи объясни простыми словами**: что сделал, зачем это клубу или студенту,
  где это в коде, как проверить руками на сайте и какой вопрос может задать комиссия.
- Если нужно моё действие (переменная в Railway, деплой) — дай короткую инструкцию.
